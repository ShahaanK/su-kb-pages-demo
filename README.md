# su-kb-pages-demo

Demo of the **publish half** of the SU AI Knowledge-Base pipeline: take Markdown
mirrored from Confluence and publish it to GitHub Pages as both human-readable
HTML and machine-readable Markdown, optimized for LLM and search crawlers.

This is the Phase 0 scaffold (ITSAI pilot). It builds and deploys with **sample
content**; wiring in the real Confluence ingest is the next step.

## Architecture

```
Confluence (ITSAI)
   |
   |  INGEST  (the su-kb converter, copied in under scripts/ingest/ -- TODO)
   |          Confluence -> Markdown + frontmatter, wikilinks resolved,
   |          attachments verified, failures dead-lettered, restricted
   |          pages dropped (visibility_signal != public)
   v
docs/**/*.md   (frontmatter + body; this is what you edit/generate)
   |
   |  PUBLISH (this repo)
   |    1. mkdocs build            -> site/ (HTML + sitemap.xml + search)
   |    2. scripts/gen_llms.py     -> site/llms.txt + site/llms-full.txt
   |    3. scripts/mirror_markdown -> site/**/index.md  (per-page .md twins)
   |    4. touch site/.nojekyll
   v
GitHub Pages   (HTML for humans + Google; .md / llms*.txt for agents + skill)
```

The **ingest half** is not in this repo yet. Phase 0 task 3/4 copies the
existing su-kb Confluence-to-Markdown converter into `scripts/ingest/` and
points its output at `docs/`. Everything downstream already works.

## Local build

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

mkdocs serve                     # live preview at http://127.0.0.1:8000/

# Full production build (what CI does):
mkdocs build
python scripts/gen_llms.py --docs docs --site site --config mkdocs.yml
python scripts/mirror_markdown.py --docs docs --site site
touch site/.nojekyll
```

## Deploy

1. Create a repo named `su-kb-pages-demo` under your GitHub account.
2. In `mkdocs.yml`, set `site_url` to `https://<your-username>.github.io/su-kb-pages-demo/`.
3. In `docs/robots.txt`, update the `Sitemap:` host to match.
4. Push to `main`. In repo Settings -> Pages, set Source = GitHub Actions.
5. The workflow in `.github/workflows/deploy.yml` builds and deploys.

## Machine-reader surface

| File | What it is |
|---|---|
| `/llms.txt` | Curated index: one bullet per page, grouped by section |
| `/llms-full.txt` | Full corpus inlined (aggressive inlining) for one-fetch consumption |
| `/<path>/index.md` | Per-page Markdown twin alongside each HTML page |
| `/sitemap.xml` | Generated by MkDocs Material; discovery for Google + AI search bots |
| `/robots.txt` | AI-bot allowlist; points to the sitemap |
| per-page `<head>` | `robots` meta, `rel=alternate` markdown link, TechArticle JSON-LD |

## What is a stub right now

- **Content** in `docs/` is sample/placeholder. Real content comes from ingest.
- **`docs/assets/css/syr.css`** is a clementine-inspired starter, not the final
  brand theme. Phase 1 replaces it with values extracted from clementine.syr.edu.
- **`scripts/ingest/`** does not exist yet (Phase 0 task 3).
- **llms generation is hand-rolled** in `scripts/`. The `mkdocs-llmstxt` plugin
  is a documented swap-in (see `requirements.txt`).
